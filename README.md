# Housekeeper · 小E 用户端

**把对话、项目、知识和长期记忆放在同一个桌面助手里。**

Housekeeper 是一款在 Windows 本机运行的 AI 秘书。你可以用自然语言安排待办、围绕项目讨论工作、检索自己的资料，也可以通过桌面小E进行语音聊天。它会从对话和工作记录中提炼长期记忆，让后续回答有机会延续你的偏好、决策与项目背景。

## 产品特点

- **围绕真实工作组织上下文**：项目、任务、资料、事件记录和项目记忆可以一起参与回答，支持追溯工作进展。
- **记忆可以持续维护**：后台从对话、资料和项目行为提炼有长期价值的信息，支持去重、补充和替代旧记忆，并保留来源。
- **工作与生活按轮切换**：对话支持自动识别、工作、生活三种模式；手动选择后跳过第一层意图识别。生活语音采用较轻的聊天流程。
- **能力由客户端配置**：在能力中心管理 Skills、HTTP 工具和 MCP 服务，查看依赖、测试结果与执行记录。
- **模型按用途分别配置**：对话、视觉、语音识别、语音合成、知识检索和联网搜索有独立的连接入口，使用自己的服务和额度。
- **本机保存业务数据**：项目、对话、记忆和索引保存在本地；公共用户端与作者个人端的数据目录和应用标识分开。

## 能做什么

| 场景 | 当前能力 | 使用条件 / 边界 |
| --- | --- | --- |
| 项目与待办 | 管理项目、任务状态、优先级、时间和依赖；通过自然语言请求创建任务 | 自然语言执行依赖模型和工具流程；信息不足时需补充，以实际写入结果为准 |
| 项目问答 | 结合当前任务、资料、事件及记忆整理进展、回顾决策 | 需要已有项目数据或关联资料 |
| 个人知识库 | 导入和检索资料，关联项目，回答中提供文档引用；支持 Obsidian Markdown 仓库 | 本地 Markdown 变更可触发重新扫描；向量检索需配置相应服务 |
| 长期记忆 | 记录偏好、工作方式、项目事实、决策和经验；查看来源、编辑内容及状态 | 自动提炼需要开启大模型并配置连接，可能产生额外 API 费用 |
| 桌面语音陪伴 | 可拖动的小E、可配置唤醒词、连续对话、打断、待机和状态反馈 | 桌面伴随和唤醒默认关闭；需配置麦克风、输出设备及语音服务 |
| 视觉理解 | 在开启摄像头上下文并满足调用条件时，将画面用于理解当前问题 | 需要摄像头与视觉模型，不是持续监控或默认录像 |
| 扩展功能 | 创建技能、接入 HTTP API / MCP 工具，并测试和查看执行记录 | 技能描述不能凭空创造底层工具；权限、必填参数与依赖必须满足 |

## Memory：让聊天形成可维护的长期记忆

系统区分三类信息：**对话历史**保存原始交流，**知识库**保存和索引资料，**长期记忆**保存未来仍有用的结论。记忆不会把所有聊天原文都塞进每次提示词。

自动更新链路为：

```text
对话 / 已扫描文档 / 项目行为 / 用户介绍
                  ↓
        本地观察队列：去重、聚合同类行为
                  ↓
        后台调用模型提炼长期信息
                  ↓
   新增 / 更新 / 替代旧记忆 / 跳过无用信息
                  ↓
        SQLite 持久化 + 来源 + 检索索引
                  ↓
    后续对话按范围读取核心记忆和相关记忆
```

- **分范围**：全局记忆用于跨项目偏好和工作方式，项目记忆用于对应项目的背景与决策。
- **可追溯**：保存来源、摘录、类型、置信度、重要性、证据次数和时间信息。
- **可更新**：重复信息可合并证据，补充信息可更新已有条目；新事实替代旧事实时，旧条目标为 `superseded` 并保留关联。
- **按需读取**：项目问答结合核心记忆与相关记忆检索；支持关键词、FTS5 全文检索和可选向量检索。生活语音走较轻的记忆读取路径。
- **后台整理**：服务运行且模型可用时异步处理观察；还会按范围生成周期复盘观察，用近期任务与既有记忆帮助整理。

例如，先表达“这个项目优先桌面端”，之后明确改为“这个项目优先移动端”，系统可将新决定与原记忆关联，保留原决定作为历史，而不是把两者都当作当前要求。是否正确识别这种变化仍取决于模型结果，可以在记忆页面检查和修正。

**当前实现会自动保存提炼结果，不逐条等待人工确认。** 置信度是记录字段，并不构成强制的保存门槛；模型可能提炼错误。“自动记忆”是本地数据维护与上下文检索，不是模型训练，也不保证记住所有信息。具体调度、纠错和限制见 [Memory 设计说明](docs/memory.md)。

## 技术架构

| 层 | 技术 | 作用 |
| --- | --- | --- |
| 界面 | React 19、TypeScript、Vite、CSS | 项目、任务、对话、设置及能力中心；玻璃质感界面 |
| 桌面容器 | Electron 38、IPC、Windows safeStorage | 桌面窗口、托盘、设备交互和模型密钥保存 |
| 本地服务 | Node.js 24、Express 5 | 业务接口、对话编排、记忆整理和工具执行 |
| 数据层 | SQLite、FTS5、sqlite-vec | 结构化业务数据、全文索引与可选语义检索 |
| 模型与检索 | 可配置模型接口、Embedding / Rerank 服务 | 回答、视觉、语音以及检索能力；服务按用途配置 |
| 扩展层 | Markdown 技能、JSON Schema、MCP SDK | 技能规则、HTTP 参数校验和 MCP 工具发现 / 调用 |
| 构建与验证 | pnpm、TypeScript、Node 测试框架、electron-builder / NSIS | 类型检查、业务测试和 Windows x64 安装包 |

应用由 Electron 承载 React 界面，本地服务处理业务与模型调用，SQLite 保存状态。工作对话根据模式组织意图、上下文、工具执行及结果；生活语音使用较轻的链路。工具的可用性、参数与执行确认由应用流程处理，技能正文用于指导行为。

## 与作者个人端的区别

- 默认独立本机运行，无需连接作者的服务器；没有作者的账号、API Key、数据库、记忆、历史对话和私人技能。
- Windows 应用名为 **Housekeeper**，业务数据保存在 `%APPDATA%/housekeeper`，界面配置使用独立的 `housekeeper-runtime` 目录。不会读取或覆盖个人端的数据。
- 首次启动进入模型设置。填写自己的服务地址、API Key 和模型名称；项目与待办可先使用。
- 桌面伴随、持续唤醒和摄像头默认关闭，按需开启。语音、视觉及搜索等能力另行配置。
- 公共版本通过本仓库的 Releases 发布，不使用作者个人服务器的更新渠道。

## 本地运行

开发环境：Node.js 24、pnpm 11（以 package.json / lockfile 为准）。正式桌面打包目前面向 Windows x64。

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm build:desktop
pnpm desktop
```

仅调试网页：`pnpm dev`，打开终端输出的 Vite 地址。浏览器开发模式下，密钥默认只在当前服务进程内保存；正式 Electron 客户端通过 Windows 安全存储保存模型密钥。

构建安装包：`pnpm package:win`。输出位于 `outputs/Housekeeper-v2.0.8/`；该命令只生成安装包，不会自动上传任何服务器。

## 首次配置

1. 设置 → 模型连接 → 对话模型：填写兼容接口 Base URL、自己的 API Key、模型名称，保存并测试。
2. 设置 → 回答方式：开启大模型回答。
3. 语音识别、语音合成、视觉模型分别配置。模型名、音色和费用以你所选服务商为准。
4. 设置 → 桌面小E：选择设备，先测试麦克风和音箱，再按需开启唤醒和摄像头。

本机运行不等于所有推理离线：云端模型、语音服务、搜索、HTTP 工具或 MCP 会接收相应请求。使用者自备服务及额度；不要把密钥填入技能正文。

## 能力中心

- **技能**：创建、编辑、导入、版本回退、检查依赖、验证触发、预览及实际执行。
- **HTTP 工具**：方法、地址、Bearer 认证、JSON Schema 参数，支持测试、启停与执行前确认。
- **MCP**：Streamable HTTP / SSE、Bearer 认证，发现并选择工具。当前不支持本机 stdio 命令及 OAuth 授权登录。
- **记录**：查看成功、失败、待确认操作；技能测试支持确认后继续后续步骤。

工作模式可使用技能和工具；生活语音沿用轻量聊天流程。依赖检查不等于业务结果已验收，应使用具体请求测试。

## 数据与边界

仅供个人可信设备使用，默认监听本机回环地址。不要直接将本机服务端口暴露到公网。可选远程模式通过环境变量配置，维护者应自行部署认证及 TLS。

模型密钥在 Electron 中使用系统安全存储。HTTP/MCP 令牌以密文保存，其解密密钥位于本机数据库目录；备份整个数据目录仍应视为敏感文件。原始录音和摄像头画面用于当前请求，勿将日志、资料库或环境配置提交到仓库。

代码采用 React + TypeScript + Vite、Electron、Node.js、SQLite，业务与工具执行共用本地服务。测试用例使用临时数据库和合成数据。

宣传网站设计另行进行。本仓库没有接入作者的私人数据或在线演示服务。
