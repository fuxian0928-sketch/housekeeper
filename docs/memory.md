# 3.3.0 记忆处理

系统分别保存原始消息、知识文档、待处理观察和可召回记忆。人设包含固定身份、性格原则和虚构背景；用户偏好及实际事件从证据中学习，不把虚构背景或助手猜测写成用户事实。

## 写入与更新

1. 对话结束、文档扫描或事件记录后，创建观察，按内容哈希和来源去重。长内容分段入队。
2. 后台整理器读取观察、来源证据和附近已有记忆，调用配置的对话模型提取长期信息。存在冲突时可再调用一次模型复核。
3. 写入前核对工作租约与证据 / 记忆版本；更新已有事实，或创建新版本并关联被替代记忆。明确的偏好和事实可自动保存，不逐条要求确认。
4. 保存来源、时间、证据、置信度、当前状态及版本关系，并更新检索索引。失败进入重试队列。

用户正在交流时优先处理前台请求，后台任务可被抢占。当前重试和抢占机制不构成消费上限。后台调用也会使用模型额度；本版尚无完整逐笔 Token 核算，不能将观察条数或消息条数当作实际请求次数。

## 召回

`AgentMemoryCoordinator` 结合用户当前输入、自动推断的项目范围、核心偏好、相关事实、工作上下文和必要的历史证据。关键词 / FTS5 可在无向量服务时工作；配置兼容 Embedding 服务后使用向量补充召回。向量查询有时间预算和失败回退。相关事实取有限数量并截断，避免每轮带入全部历史。

有明确“之前、继续、上次”等线索时，可以回查原始聊天作为证据。项目、文档和执行结果优先以当前保存状态为准；旧助手回答不自动升级为事实。外部腾讯记忆读取适配是可选组件，需要用户单独配置，不会自动把全部数据上传。

## 星空与控制

记忆星空读取当前记忆、来源、事件和替代历史，形成节点与关系。它展示数据库中的关联，不负责凭空生成事件。支持查看来源与变化，也保留直接记忆工具的新增、替代和遗忘路径。

## 边界

- 记忆学习是应用数据更新，不是模型训练。
- 模型可能漏提取、误判偏好或错误合并；来源与版本用于核对和纠正。
- 自动整理默认使用配置的对话服务，会产生额外 API 调用；本版没有独立消费预算。
- 本仓库不包含作者的真实用户档案、个人记忆、聊天、数据库或文档。
